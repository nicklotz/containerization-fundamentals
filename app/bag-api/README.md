# bag-api

bag-api is the HTTP API of BagTrack. It stores the checked bags at an airport hub and records every scan of a bag. It is written in Python with FastAPI.

## Checkpoints

Every bag passes these checkpoints in this order:

1. `checked_in`
2. `security`
3. `sorted`
4. `loaded`
5. `unloaded`
6. `claimed`

A scan can only move a bag to its next checkpoint. bag-api answers any other scan with HTTP 409 and a message that names the next checkpoint.

## Environment variables

| Variable | Default | Meaning |
|---|---|---|
| `DATABASE_URL` | not set | PostgreSQL URL, for example `postgresql://bagtrack:secret@postgres:5432/bagtrack`. If it is not set, bag-api keeps its data in memory. |
| `HUB` | `ORD` | Airport code of the hub. The board shows it in its title. |
| `APP_VERSION` | `dev` | Version string that `/api/info` returns. |
| `SEED` | `true` | If `true` and the store is empty at startup, bag-api adds 12 sample bags. |

## Endpoints

| Request | Answer |
|---|---|
| `GET /healthz` | `{"status": "ok"}` while the process runs. Use it for liveness probes. |
| `GET /readyz` | 200 when the storage answers. 503 when PostgreSQL cannot be reached. Use it for readiness probes. |
| `GET /api/info` | Service name, version, hostname, hub and storage kind (`memory` or `postgres`). |
| `GET /api/bags` | Bags, most recently updated first. Optional query parameters: `flight`, `status`, `limit` (1 to 1000). |
| `POST /api/bags` | Checks in a bag. Body: `{"flight": "FL101", "passenger": "Garcia", "destination": "SFO"}`. `tag` is optional. Answers 201, or 409 if the tag exists. |
| `GET /api/bags/{tag}` | One bag, or 404. |
| `POST /api/bags/{tag}/scans` | Body: `{"checkpoint": "security", "scanner": "sc-1"}`. Answers the updated bag, 404 for an unknown bag, or 409 if the checkpoint is not the next one. |
| `GET /api/bags/{tag}/scans` | The scans of one bag, oldest first. |
| `GET /api/stats` | `{"total": 12, "by_status": {"checked_in": 2, ...}}` with every checkpoint. |
| `GET /` | Service name, version and the paths of the documentation and the bag list. |
| `GET /docs` | Interactive API documentation, generated by FastAPI. |

## Run it on your machine

You need Python 3.12 or later.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn bagtrack.main:app --host 0.0.0.0 --port 8000
```

Open http://localhost:8000/docs, or use curl:

```bash
curl localhost:8000/api/bags
curl -X POST localhost:8000/api/bags -H 'Content-Type: application/json' \
  -d '{"flight": "FL101", "passenger": "Garcia", "destination": "SFO"}'
```

bag-api logs one line at startup with its version, hub and storage. uvicorn logs one line per request.

## PostgreSQL

When `DATABASE_URL` is set, bag-api creates the `bags` and `scans` tables on the first connection that works.

bag-api starts even when PostgreSQL cannot be reached yet. Until the database answers, `/readyz` and the API calls that need the database answer 503. Each connection attempt gives up after 2 seconds.

To add the sample bags to a database without starting bag-api:

```bash
DATABASE_URL=postgresql://bagtrack:secret@postgres:5432/bagtrack python -m bagtrack.seed
```

The command skips bags whose tag already exists and prints how many bags it added. It exits with code 1 if `DATABASE_URL` is not set or the database cannot be reached.

## Tests

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Run pytest as `python -m pytest` from this folder, so that Python finds the `bagtrack` package.

The tests in `tests/test_postgres.py` run only when `TEST_DATABASE_URL` is set to a PostgreSQL database. Otherwise pytest skips them.
